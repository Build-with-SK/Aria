## Safe local use

From the isolated worktree in PowerShell, using the existing Windows venv:

```powershell
..\trading-intelligence-system\venv\Scripts\python.exe scripts\multiasset_research.py
$researchTests = Get-ChildItem tests/test_multiasset_*.py | ForEach-Object FullName
..\trading-intelligence-system\venv\Scripts\python.exe -m pytest -q $researchTests
```

The first command prints disconnected extension status; no network, terminal or
database is opened. For research, pass `--input PATH_TO_RESEARCH_REQUEST.json`.
Schema: `src/research/multiasset.py:ResearchRequest` (`instrument`, `bars`, aware
`as_of`, optional `family`, `timeframe`, `regime`, `evidence`). Every candle includes
provenance. A usable fixture is generated by tests, never presented as live prices.

```powershell
cd frontend
npm ci
npm run build
node scripts/verify-multiasset.mjs
node scripts/verify-launch-routes.mjs
```

No additional npm dependencies were added. This machine reused the already
installed frontend dependencies via a worktree junction; clean machines use the
existing lockfile. A separate hash-pinned minimal Python research environment is
provided in `requirements-trading-research.lock`; it avoids the vulnerable shared
model/broker environment. See `DEPENDENCY_AUDIT.md` for audit scope and limits.

Do not start a second backend in this worktree. After independent review and a
separate owner-directed integration/restart, use the existing README Run ARIA
procedure in the main checkout. The panel appears inside **Portfolio**. Existing
owner authentication protects both new routes:

- `GET /api/trading/workspace`: truthful disconnected/disabled extension status.
- `POST /api/trading/research`: supplied-candle research; no persistence or send.

`ReviewStore` is a tested library with an explicit database path, not an activated
approval endpoint/worker. `MT5ReadOnlyAdapter` is a tested SDK boundary, not a
connected broker. See [operations](OPERATIONS.md) before changing either.
